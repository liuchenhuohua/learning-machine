# 多项目窗口与历史差异设计规格

## 目标

为 Learning Machine 增加两个相互独立但可一起交付的桌面体验：

1. 用户在任意项目内都能从左下角打开新的独立窗口，并在新窗口中选择另一个项目。
2. 历史页参考 GitHub Desktop，以“提交 → 修改文件 → 文件差异”的方式展示每次项目书和反馈变化。

## 当前问题与根因

- 侧栏只有归档和关闭项目，没有创建独立窗口的入口。
- `git_project_diff` 固定运行 `git show ... -- project.md`。反馈提交修改的是 `feedback/*.md`，因此反馈差异返回空字符串。
- 历史页把原始 diff 放进单个 `<pre>`，没有文件列表、行号、增删统计或明确的视觉层级。
- 原生项目没有提交时仍会回退到演示历史，可能再次混入不属于当前项目的信息。

## 多窗口设计

### 入口与行为

- 在项目侧栏左下角、归档与关闭操作上方增加“在新窗口打开项目”按钮，使用窗口加号图标。
- 点击后由 Rust 命令创建新的 Tauri Webview 窗口。
- 新窗口进入现有项目选择页，不预选当前项目；用户可以打开最近项目、选择已有目录或创建项目。
- 当前窗口的项目、页面和未保存编辑状态保持不变。
- 每个窗口拥有独立的 Zustand 运行时状态；持久化内容仍只包含主题和最近项目，不持久化当前项目。

### 窗口约束

- 标题为 `Learning Machine · 选择项目`。
- 初始尺寸 1180 × 780，最小尺寸 1000 × 680，居中显示。
- 使用唯一窗口标签，允许同时创建多个窗口。
- 浏览器演示模式不伪造真正多窗口：点击时给出“桌面版支持多窗口”的说明。
- 窗口创建失败时在当前界面显示可理解的错误，不改变现有窗口状态。

### 安全边界

- 由 Rust 后端创建窗口，不向前端开放宽泛的窗口管理权限。
- 新窗口只加载应用自身 URL，不把项目路径拼入 URL，也不跨窗口传输文件内容。
- Tauri capability 的窗口匹配范围仅扩展到 `main` 和应用生成的 `project-*` 标签；新窗口只获得现有应用功能所需的权限。

## 历史与差异数据设计

### 后端接口

保留 `git_history(project_root)`，用两个按需接口替换固定的 `git_project_diff`：

1. `git_commit_files(project_root, hash) -> Vec<GitChangedFile>`
   - 通过 `git diff-tree --root --no-commit-id --name-status -r <hash>` 获取本次提交涉及的全部文件。
   - 返回 `path`、`status`（added / modified / deleted / renamed）和可选的原路径。
2. `git_file_diff(project_root, hash, relative_path) -> String`
   - 通过 `git show --format= --find-renames --unified=3 <hash> -- <path>` 返回选中文件的统一差异。
   - `relative_path` 必须经过项目根目录安全校验；hash 必须限制为十六进制 Git 对象 ID，禁止成为额外命令参数。

前端只在用户选择提交后加载文件列表，并只在选择文件后加载该文件差异，避免一次读取整个历史。

### 前端模型

新增以下领域类型：

- `GitChangedFile`：路径、状态、旧路径。
- `DiffFile`：文件头与多个 `DiffHunk`。
- `DiffHunk`：旧/新起始行以及 `DiffLine[]`。
- `DiffLine`：`context | addition | deletion | meta`、旧行号、新行号、正文。

使用纯函数 `parseUnifiedDiff(raw)` 把 Git 文本转换成展示模型。解析失败时保留原始差异文本作为降级视图，不能显示空白页面。

## 历史页交互设计

### 标准宽度

历史页使用 GitHub Desktop 风格的三段结构：

1. 提交列表：时间、提交说明、类型标签、短 hash。
2. 修改文件列表：文件状态图标、路径、选中状态；反馈提交自动选中对应 `feedback/*.md`。
3. 差异阅读区：文件路径、增删统计、显示方式切换和差异正文。

点击提交后保持在同一历史页，不再跳转到孤立的“项目书版本变化”页面。默认选中该提交的第一个文件。

### 差异显示

- 默认使用 Unified 模式：删除行红色、增加行绿色、上下文行中性，旧/新行号分列显示。
- 提供 Split 模式：旧版本在左、当前版本在右；新增或删除文件时缺失一侧显示空白占位。
- 文件标题明确标识“新增文件”“修改文件”“删除文件”或“重命名”。
- 新反馈通常是新增 Markdown 文件，因此会以整份绿色新增内容出现；后续若反馈文件发生变化，则只突出实际变化行。
- 空提交或没有可展示文本差异时显示明确空状态，不展示演示内容。

### 响应式行为

- 历史工作区可用宽度至少 900px 时显示三栏。
- 更窄时保留提交栏，文件列表收纳到差异区顶部的文件选择器中，确保差异正文仍有足够宽度。
- 各栏独立滚动，选择提交或文件时将对应差异滚动到顶部。

## 状态与错误处理

- 切换项目时立即清空上一项目的提交、文件和差异状态，避免跨项目残留。
- 加载提交、文件和差异分别显示局部加载状态；后一步失败不清空前一步已经成功的数据。
- Git 不可用、提交不存在、文件为二进制或路径无效时显示具体错误。
- 原生项目没有提交时显示“还没有历史记录”；仅浏览器演示项目可以使用示例历史。

## 文件边界

- `src/components/layout/WorkspaceShell.tsx`：新增窗口入口和错误提示。
- `src/lib/desktop.ts`：窗口、提交文件和单文件差异 API。
- `src/types/domain.ts`：Git 文件与差异领域类型。
- `src/features/history/HistoryWorkspace.tsx`：负责选择和数据加载，不承担 diff 文本解析。
- `src/features/history/diffParser.ts`：纯函数解析统一差异。
- `src/features/history/DiffViewer.tsx`：Unified / Split 展示组件。
- `src/styles.css`：多窗口按钮、三栏历史和差异视觉样式。
- `src-tauri/src/lib.rs`：受约束的窗口创建和 Git 查询命令。
- `src-tauri/capabilities/default.json`：允许应用生成的 `project-*` 窗口使用现有命令和插件权限。

## 测试策略

### 前端

- `diffParser` 单元测试覆盖新增文件、修改文件、删除行、多 hunk 和空差异。
- 历史页组件测试覆盖选择反馈提交后请求其实际文件、自动选中第一个文件、切换 Unified / Split、无历史空状态。
- 侧栏测试覆盖点击新窗口入口调用桌面 API，且当前项目不被关闭。

### Rust

- hash 校验接受常见 SHA-1/SHA-256 十六进制长度并拒绝命令参数注入。
- Git 文件状态解析覆盖 A/M/D/R。
- 新窗口命令使用唯一标签且窗口构建失败能返回错误。

### 集成验证

- 创建两份反馈后，历史中存在两次独立反馈提交；每次都列出正确的反馈文件和新增内容。
- 修改项目书后能显示实际增删行。
- 从项目 A 打开新窗口，在新窗口选择项目 B，两个窗口保持各自项目。
- 在 1440 × 900 和最小 1000 × 680 窗口下验证布局与独立滚动。

## 非目标

- 不实现提交范围多选、丢弃行、撤销提交、分支管理或 GitHub 同步。
- 不允许编辑历史版本或已保存反馈。
- 不在窗口之间实时同步当前页面和临时编辑内容。
